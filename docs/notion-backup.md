# 커플도장 독립 Notion 백업

사이트는 도장 원본과 변경 대기를 Cloudflare D1에 함께 기록합니다. `.github/workflows/notion-backup.yml`이 매시 34분에 GitHub Actions에서 `scripts/notion-backup.mjs`를 실행합니다. 이 프로그램은 사이트의 인증된 백업 API와 Notion REST API를 직접 사용합니다. ChatGPT 예약, LLM, 연결 앱 도구, 열린 브라우저, 개인 PC가 필요하지 않습니다. 기존 ChatGPT 예약은 중지했습니다.

## 최초 연결

1. 선택한 Notion 계정에서 내부 통합을 만들고 콘텐츠 읽기·삽입·업데이트 권한을 허용합니다. ‘커플도장 백업’ 상위 페이지와 그 아래 기훈·빛나 데이터베이스에 이 통합을 연결합니다.
2. https://github.com/aakn232/dozang/settings/secrets/actions 에서 `NOTION_API_TOKEN`에 내부 통합 시크릿을 저장합니다. 채팅·소스·이슈에 키를 올리지 않습니다.
3. https://dozang-aakn232.foggygiant.chatgpt.site/backup-setup 에 사이트 소유자 계정으로 로그인합니다. 여기에서 복사한 JSON을 같은 GitHub Secrets 화면에 `DOZANG_BACKUP_CONFIG`라는 이름으로 저장합니다. 이 로그인은 설정 값 공개를 소유자에게만 허용하기 위한 것이며 실제 백업은 GitHub에서 독립 실행됩니다.
4. GitHub Actions의 ‘Notion backup’에서 Run workflow로 실행하고 결과를 확인합니다. 비밀정보 누락, 연결 실패, 검증 실패는 성공으로 처리하지 않습니다. 사이트 관리자 모드에서도 최근 실행·완료·대기·오류 건수를 확인합니다.

코드 배포만으로 GitHub Secrets가 등록되지는 않습니다. 비밀정보가 모두 등록되고 실제 실행이 성공하기 전에는 자동 백업 연결 완료로 안내하지 않습니다.

## 서버의 비밀 설정

Sites 런타임에만 다음을 secret으로 보관합니다. `.openai/hosting.json`, GitHub 소스, 일반 방문자 응답에는 저장하지 않습니다.

- `DOZANG_BACKUP_KEY`: 256비트 백업 작업 인증값. 작업 목록 및 실행 결과 기록에 필요합니다.
- `DOZANG_BACKUP_SITE_ACCESS`: Sites가 해당 사이트에 발급한 서비스 접근값. GitHub 요청은 해당 사이트에만 `OAI-Sites-Authorization` 헤더로 전달합니다.
- `DOZANG_BACKUP_OWNER_EMAIL`: Sites 소유자 이메일. 설정 페이지와 API는 플랫폼이 인증한 이메일을 서버에서 대조합니다. 날짜 비밀번호로 이 설정에 접근할 수 없습니다.

Notion API 키는 GitHub Secrets에만 있습니다. 설정 화면의 연결 JSON은 사이트 접근값과 백업 인증값을 포함하므로 소유자만 열람할 수 있습니다. 서버 값이 교체되면 연결 화면에서 새 값을 복사해 GitHub Secret도 갱신합니다.

## 실행과 검증

- 두 데이터 소스의 스키마와 Notion 접근부터 확인합니다. 위치는 `.openai/backup.json`을 따릅니다.
- 키로 인증해 대기 목록 전체를 ID 커서로 읽습니다. 작업 삭제 때문에 목록이 누락되지 않도록 처리 전에 목록을 수집합니다.
- 작업별 ticket과 15분 lease로 동시 실행과 오래된 완료 요청을 차단합니다. GitHub에서도 concurrency를 적용합니다.
- 도장 ID를 해당 데이터 소스에서 정확히 조회합니다. 중복이면 덮어쓰지 않고 오류로 남깁니다. 이전 페이지가 사라지거나 이동됐을 때도 조용히 중복 생성하지 않습니다.
- 새 도장은 한 페이지로 생성합니다. 읽기용 원문과 복원용 JSON 코드 블록을 함께 저장하며 10,000자·공백·줄바꿈·이모지를 복원할 수 있습니다.
- 삭제·복원은 같은 페이지의 상태와 복원 헤더를 갱신합니다. 본문 원문은 지우지 않습니다. 삭제 시각은 복원할 때 명시적으로 비웁니다.
- 쓰기 후 페이지와 모든 본문 블록을 페이지네이션으로 다시 읽습니다. 원문 SHA256, 날짜, 작성·삭제 시각, ID, 도장판, 상태, 동기화 버전을 대조한 뒤에만 서버에 완료를 기록합니다. Notion 날짜 속성의 분 단위 표시에 관계없이 복원 JSON에는 원래 시각을 그대로 보존합니다.
- 생성 응답이 불확실하면 즉시 다시 생성하지 않습니다. 다음 실행에서 ID 조회부터 다시 하므로 중복을 피합니다. 읽기·멱등 갱신은 일시 오류/429에 제한적으로 재시도합니다.
- 원문이 손상된 기존 백업은 자동으로 덮어쓰지 않습니다. 대기를 보존하고 실패로 표시합니다. 서버 원본과 JSON 내보내기로 확인한 뒤 복구합니다.
- 로그에는 건수와 일반 오류만 남기고 토큰·작업 티켓·도장 내용은 출력하지 않습니다. 워크플로는 내용 읽기 권한만 갖고, 빌드·배포·커밋을 수행하지 않습니다.

## 보존 범위와 예약 제한

사이트 저장은 Notion 장애와 독립적이며 원본 보관과 대기 등록은 하나의 D1 트랜잭션입니다. 외부 복사 전의 데이터는 D1 전체 손실에 대비한 Notion 사본이 아직 없습니다. 연결 장애 중에는 대기를 보존하고 다음 실행에서 재시도합니다.

GitHub의 cron은 정확한 시각을 보장하지 않으며 부하에 따라 지연될 수 있습니다. 공개 저장소에 60일간 활동이 없으면 예약 워크플로가 자동 중지될 수 있습니다. GitHub의 중지 안내를 받거나 관리자 화면의 최근 실행이 오래됐으면 Actions에서 활성화하고 Run workflow로 확인합니다. 사이트는 최근 3시간 실행이 없으면 관리자에게 표시합니다. 정확한 상시 예약 보장이 필요하면 사용자가 소유한 Cloudflare Cron 등 전용 스케줄러 연결이 필요합니다.

## Notion 구조와 복원

‘커플도장 백업’ 아래 ‘기훈 도장판’과 ‘빛나 도장판’이 있고 각각 별도 데이터베이스를 사용합니다. 도장별로 제목, ID, 도장 날짜, 작성 시각, 정상/삭제됨, 삭제 시각, 백업 시각, 형식 버전, 원문 SHA256, 동기화 버전을 저장합니다.

로고 5번 → 오늘의 비밀번호 → 백업과 복원에서 삭제 기록 복원과 JSON 내보내기/가져오기를 할 수 있습니다. 가져오기는 미리보기 후 확인하며 기존 ID를 덮어쓰지 않습니다. 삭제 상태로 가져온 기록은 휴지통에 남습니다.

D1 전체 손실 시 Notion의 모든 도장 페이지를 페이지네이션으로 읽고 복원 JSON을 검증해 `dozang-backup` 형식으로 묶습니다. `scripts/notion_restore.mjs`는 원본 Notion Markdown에서 복원 파일을 만듭니다. 도장판별 1,000개, 12MB 이하로 나누어 관리자 화면에서 가져옵니다. 자동 백업 프로그램은 임의로 사이트를 복원하지 않습니다.
