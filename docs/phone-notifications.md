# 휴대폰 새 칭찬 알림

각 기기에서 받을 도장판을 선택하고 ‘새 칭찬 알림’ → ‘기훈/빛나 알림 켜기’ → 브라우저의 허용을 선택합니다. 상대방도 자기 휴대폰에서 같은 절차로 자신이 받을 도장판을 켭니다. 양쪽 모두 받으려면 각 도장판에서 켭니다. 로그인은 필요하지 않습니다. 테스트 알림으로 잠금 화면/알림창에서 수신을 확인할 수 있습니다.

아이폰·아이패드는 iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 웹 앱이어야 합니다. Safari의 공유 → 홈 화면에 추가 후 홈 화면 아이콘으로 열어 설정합니다. Android는 Chrome 등의 지원 브라우저에서 설정합니다. 인앱 브라우저나 지원하지 않는 브라우저에서는 별도 안내를 표시합니다. OS의 집중 모드·알림 차단·네트워크 상태에 따라 표시가 지연될 수 있습니다.

## 서버 저장과 전송

- 기기의 endpoint, p256dh, auth 및 두 도장판의 수신 선택은 D1 `push_subscriptions`에 보관합니다. 구독 목록이나 비밀키는 일반 조회에 공개하지 않습니다. 구독 조회·해제에는 해당 브라우저의 endpoint와 두 키가 필요합니다.
- 공개 `/api/push` GET은 VAPID 공개키와 구성 여부만 제공합니다. 개인키 `PUSH_VAPID_PRIVATE_KEY`는 Sites의 비밀 런타임 설정에만 있습니다. 키를 임의로 바꾸면 기존 구독은 다시 연결해야 합니다.
- 새 도장 저장과 `push_events`, 기기별 `push_deliveries` 추가는 같은 D1 batch 트랜잭션입니다. 기존 기록, 동일 도장 요청 재시도, 삭제/복원·JSON 가져오기는 새 칭찬 알림을 생성하지 않습니다.
- 게시글 저장 후 Workers `waitUntil`로 전송합니다. 데이터 저장은 푸시 제공자의 장애와 독립적입니다. `@block65/webcrypto-web-push` 2.x를 사용해 RFC 8291 aes128gcm 암호화와 RFC 8292 VAPID 인증을 구성하며 fetch 기반 HTTPS만 사용합니다.
- endpoint는 HTTPS의 Google FCM, Mozilla Push, Apple Push 및 Windows WNS 호스트로 제한하고 리다이렉트를 따르지 않습니다. 알림은 도장판 이름과 링크만 포함하며 글 내용은 잠금 화면에 노출하지 않습니다.
- 전송에 2분 lease, 기기/게시글 고유키, 성공 수신 기록을 사용합니다. 서비스 워커의 같은 tag 알림은 교체되며, 네트워크 응답이 유실되는 경우 전송의 정확히 한 번 도착을 보장하지는 않습니다.
- 전송 실패는 1분부터 최대 1시간까지 간격을 늘려 대기합니다. 새 게시글·구독 연결 시 및 GitHub의 시간별 기존 백업 작업에서 재시도합니다. 알림 이벤트는 24시간 후 정리하며 오래된 칭찬을 새로 구독한 기기로 소급 전송하지 않습니다. 404/410 구독은 만료된 기기로 판단해 제거합니다.
- 기기가 특정 도장판 알림을 끄면 그 도장판의 대기 전송도 제거합니다. 두 도장판 모두 끄면 서버 구독과 브라우저 구독을 해제합니다. 이미 푸시 서비스에 전달된 알림은 취소할 수 없습니다. 전송 직전 삭제된 게시글과 해제된 구독을 다시 확인합니다.
- Push 전용 service worker는 웹 페이지나 칭찬 데이터를 캐시하지 않습니다. 알림을 누르면 같은 사이트의 해당 도장판과 글을 엽니다. 앱을 열어 두거나 ChatGPT 예약 작업이 실행될 필요가 없습니다.

## 운영 확인

`POST /api/push/worker`는 기존 백업 실행 키로 보호되며 완료·실패·대기 건수만 반환합니다. GitHub Actions의 ‘Retry queued phone notifications’ 단계가 호출합니다. 서비스 접근값은 해당 사이트의 `OAI-Sites-Authorization` 헤더에만 전달합니다. 로그에 구독 endpoint·인증키·VAPID 개인키·게시글 원문을 남기지 않습니다.

자동 검증은 암호화 payload의 독립 복호화, VAPID 서명 검증, 도장판 분리, 중복 방지, 동시 lease, 실패 후 재시도, 만료/해제/삭제 처리를 확인합니다. 실제 휴대폰 알림 표시와 OS 허용 상태는 사용자가 ‘테스트 알림’으로 확인합니다.
